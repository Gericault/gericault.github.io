# Django Hierarchy
Django will create a list of files in your directory;
![Select-name]({{site.baseurl}}/images/Pasted image 20241114194153.png)
**init.py** is an empty file that tells python to treat this directory like a python package.
**asgi and wsgi** are special configuration files  used by Django to communicate with ASGI or WSGI compatible web servers to serve your project - we will not need to deal with these files today.
**settings.py** contains project settings - installs apps, plugin settings, middleware used and to modify database engines.
**urls.py** This is the table of contents for our site; it contains our URL declarations used to configure routes to different Django applications.
**manage.py** - special file that acts as a command line tool, allows user to make database migrations, run a python server, manage users via admin panel and more

## Django applications
A Django app is what executes code or serves a webpage.
An app could be a blog system, a database, an authentication system or a survey, Apps are standalone and plug and play.
A project can contain multiple apps, an app can be in multiple projects.

Using Django we can have templates inherit from other templates - this can be powerful!

Head over to admin.py; by referencing the model here and registering to the admin panel we can view and edit via said panel.
![Select-name]({{site.baseurl}}/images/Pasted image 20250411205441.png)

As we create models we will need do what is called a migration - this is pre-written code that will go and create the corresponding code in a language (such as SQL or MongoDB) effectively converting it into a database for our use.

Any time you make a change to your database model you need to make a migration, this allows Django to update your database while ensuring the data itself is not compromised while making changes to the schema.
Do this by typing 
{% highlight terminal %}
python manage.py makemigrations 
{% end highlight %}
into your terminal, and then apply the migration by typing 
{% highlight terminal %}
python manage.py migrate
{% end highlight %}
this applies the migration and updates the database for you.

**To summarize you need to make your migration and then apply it** - do this every time you make a change to your database!

Migrations let you change your models over time as you develop your project, without  needing to delete your database or tables and make new ones - You can upgrade and change your database live without losing data!
